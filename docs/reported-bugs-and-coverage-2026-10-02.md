## Test-environment failures are not automatically app bugs

Historical unscoped Save/back buttons, overlays intercepting clicks, re-clicking project cards beneath an open detail page, missing authentication storage states, and WebKit DNS/network suspension were reported in test work. Preserve their evidence, but do not classify a product bug without reproducing the intended user workflow. The current three Playwright project-form cases remain unexecuted because Chromium installation was unavailable.

## Shared-workspace code finding

`saveEstimate` and `saveProject` populated both `userId` and `ownerUid` with the active user's UID for a new record. `withSharedOwnerMetadata` respected those existing fields before considering the resolved company owner, so an invited employee saved records under her own UID. `_startSyncWithOwner` filters by userId: employee sees employee + owner, owner sees owner only. This reproduces the reported asymmetry without touching live data.

New forms now leave ownership fields empty until the existing owner resolver supplies the company owner. Existing record ownership is preserved; `createdByUid`/`updatedByUid` identify the actual actor. The test also verifies unrelated-company rows do not enter either user's local list. This is client behavior testing, not server authorization; Firestore rules still require separate repair.

Previously misfiled records are not automatically moved by this change. Review record ownership, invitation/profile linkage and backups before any migration. No production data, access rules or deployment was changed during this audit.
